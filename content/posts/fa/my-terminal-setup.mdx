ده سال است که نسخه‌های مختلفی از یک تنظیمات شل را با خودم می‌کشم. هر چند وقت یک‌بار یک پرامپت جدید، یک راه تازه برای پریدن بین پوشه‌ها، یک ابزاری که `grep` را سریع‌تر می‌کند پیدا می‌کردم و یک شب را خرج سوار کردنش می‌کردم. تنظیمات بزرگ‌تر می‌شد. سرعت من نه.

زمستان گذشته نشستم پای فایل و شمردم داخلش چیست. حدود ششصد خط، که صادقانه می‌توانستم شاید هشتاد خطش را توضیح بدهم. پس از صفر ساختمش و هر خط را فقط وقتی برگرداندم که در یک روز کاری معمولی دلم برایش تنگ شد.

## چه چیزهایی واقعاً زنده ماندند

| ابزار | کارش |
| --- | --- |
| fish | خود شل، با completionهایی که بدون تنظیمات کار می‌کنند |
| starship | پرامپت، بیشتر برای وضعیت git و کد خروج |
| zoxide | `z proj` به‌جای تایپ کردن مسیر برای بار چهارصدم |
| fzf | جست‌وجوی فازی در تاریخچه، فایل‌ها و برنچ‌ها |
| ripgrep | جست‌وجو، که تنها چیزی است که بیشتر از خود شل استفاده می‌کنم |
| lazygit | وقتی rebase بد پیش می‌رود و می‌خواهم ببینمش |

شش ابزار. سه‌تایشان به شکلی از ده سال پیش در تنظیماتم بودند و دانستن همین یک چیز درباره‌ی خودم مفید است.

## قاعده‌هایی که آخرش به آن‌ها رسیدم

### alias برای چیزهایی است که غلط تایپ می‌کنم

قبلاً برای همه‌چیز alias داشتم. مشکل این است که alias یک زبان خصوصی است و من حداقل روی سه دستگاه کار می‌کنم که فقط یکی‌شان دقیقاً همین تنظیمات را دارد. حالا alias فقط وقتی وجود دارد که دستور طولانی باشد و زیر فشار غلط تایپش کنم.

```bash
# طولانی است، و همیشه هم غلط تایپش می‌کنم
alias gst='git status --short --branch'
alias lg='lazygit'
alias serve='python3 -m http.server 8000'

# بقیه را عمداً کامل تایپ می‌کنم
```

خط آخر مهم‌ترین است. اگر `git rebase --interactive main` را چند صد بار تایپ کنم، دانشش در انگشتانم می‌ماند و روی یک ماشین قرضی هم لازم نیست dotfilesم کار کنند.

### همه‌چیز در یک ریپازیتوری است

تنظیمات، اسکریپت نصب، و فهرستی از این‌که هر برنامه چه کاری می‌کند و چرا. راه انداختن یک ماشین جدید یک دستور است و حدود چهار دقیقه، و readme هر فایل را توضیح می‌دهد تا منِ آینده مجبور نباشم تصمیمی را که در سال 2019 گرفته‌ام دوباره مهندسی معکوس کنم.

> اگر ابزاری برای توجیه خودش یک پاراگراف توضیح لازم دارد، حق ماندن ندارد.

### هیچ‌چیزی که هر هفته آپدیت بخواهد

پرامپت‌های پرزرق‌وبرق و پلاگین‌منیجرهایی با دویست پکیج را امتحان کرده‌ام. دو هفته سرگرم‌کننده‌اند، بعد نگه‌داری می‌خواهند، و نگه‌داری هیچ‌وقت آن بخشی از روز نیست که منتظرش باشم. تنظیمات فعلی یازده ماه است که بدون تغییر مانده، جز یک رنگ.

## تنظیمات واقعی

بیشتر چیزی که مانده اصلاً ابزار نیست. چند تنظیم است که شل را وادار می‌کند همان‌طوری رفتار کند که انتظار دارم:

```bash
set -g fish_greeting ""
abbr --add gco "git checkout"
abbr --add gst "git status --short --branch"
set -x EDITOR nvim
set -x PAGER less
```

abbr به‌جای alias، چون داخل پرامپت باز می‌شوند و قبل از زدن Enter می‌بینم چه چیزی اجرا خواهد شد. همین یک تغییر بیشتر از هر پلاگینی نجاتم داده.

## به کسی که می‌خواهد از صفر شروع کند چه می‌گویم

پنج کاری را که بیشتر از همه در ترمینال انجام می‌دهی بنویس. همان‌ها را درست تنظیم کن و یک ماه به بقیه‌ی چیزها دست نزن. آن‌چه دلت برایش تنگ می‌شود خودش می‌گوید چه اضافه کن، و فهرستش معمولاً کوتاه‌تر از انتظار است.

نیمه‌ی دیگر ماجرا فنی نیست: ارزش یک تنظیمات در این است که دیگر متوجهش نشوی. تنظیماتی که هنوز دارد تنظیم می‌شود، تنظیماتی است که هنوز دارد توجهت را می‌خورد. مال من الان خسته‌کننده است و امسال به همین دلیل کار خیلی بیشتری تمام کردم.
